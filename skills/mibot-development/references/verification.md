# 验证与交付

## 环境与命令

使用 Node.js 24，原生依赖 ABI 与运行 Node 对齐。先读实际 `package.json` 和脚本；以下命令从 Core 根目录执行。完整测试默认查找同级 `mibot-plugins`，不存在时使用 `TeleBox-Plugins`；确认它对应本次需要的工作树和版本。

| 目的 | 命令 | 证明范围 |
| --- | --- | --- |
| Core 类型检查 | `npm run typecheck:v2` | Core TypeScript 契约 |
| 扩展类型检查 | `node node_modules/typescript/bin/tsc -p ../TeleBox-Plugins/tsconfig.v2.json` | 按实际插件路径调整；两仓 SDK 类型兼容 |
| 生产构建 | `npm run package:v2` | Core 独立预编译，排除测试源码 |
| 单插件候选构建 | `node scripts/build-v2-plugin.cjs example ../TeleBox-Plugins/example v2.ts` | 打包同包源码，外部依赖仍需宿主提供；资源文件在末尾显式传入 |
| 单插件回归 | `node --test ../TeleBox-Plugins/scripts/example-v2.test.js` | 先构建 Core；测试按实际名称选择 |
| 完整回归 | `npm run test:v2` | 两仓类型检查、Core、构建链与匹配命名的插件测试 |
| 扩展加载卸载 | `npm run test:plugins:v2` | 构建全部可安装扩展，用真实 Host 加载卸载，外部操作禁止 |
| 离线集成 | `npm run check:v2` | 构建后执行；临时存储与模拟传输，不登录 Telegram |

Core 独立 `package:v2` / `check:v2` 不要求同级插件目录。插件候选输出为 `dist/v2-plugins/<id>/<revision>/`，以构建器返回的 manifest 和 revision 为准，不手工修改不可变目录。

## 按风险选择检查

- **文档或 Skill**：核对来源、链接、示例和说明的执行语义；运行 Skill 校验器。含可运行代码示例时，在隔离目录验证类型、构建和关键行为，无需因纯文案修改启动全仓测试。
- **纯业务逻辑**：针对实际变更测试输入、输出和失败分支。保留已支持的命令参数及数据格式。
- **命令、帮助、权限**：通过真实 Host 检查分发、当前前缀、空参数、子路径帮助、编辑消息和拒绝路径；拒绝时不触发业务状态或外部副作用。
- **协议适配**：使用实际 Api 类型、ID 类型及序列化，在模拟响应中覆盖分页和 RPC 错误。服务端授权及真实数据效果仍需另外验证。
- **有状态或长期任务**：测试数据重载、重复加载、任务进行中的取消、卸载超时和清理；仅检查实例能创建不足以证明资源归属正确。
- **SDK / Host / 构建 / 归属调整**：运行完整 `test:v2`；影响插件加载或生命周期时加 `test:plugins:v2`，影响运行入口时加独立构建和离线检查。

测试需断言可观察行为或生命周期不变量；不要只匹配源码字符串、复制实现表达式或重复已有检查。复现修复先证明相关测试能在修复前失败。

用户工作区有无关变更时可使用隔离工作树或副本，但须包含本次未提交修改并记录实际基线。隔离测试不能把另一个分支的插件结果当成本次交付分支的验证结果。

## 交付边界

- 检查 diff、类型与相关测试后，按项目 `AGENTS.md` 处理版本和提交。Core 代码批次同步 `package.json`、lockfile 两处版本及 `CHANGELOG.md`；纯文档和 Skill 修改不递增应用代码版本。
- 仅提交本次相关文件。当前项目要求优先由配置的 Pi agent 提交和正常推送；不可用时按已有授权自行完成。目标分支由会话和实际工作树确定，不擅自合并或强推。
- SDK 能力变化须注明升级顺序：先升级支持所需声明能力的 Core，再安装相应插件。扩展更新说明给出 `.tpm update <id>`，Core 更新说明给出 `.update`。
- 说明已验证的行为、失败检查和剩余限制。单元测试、真实序列化、Host 集成、线上部署与真实账号测试分别报告，不能互相替代。
- 自动测试使用临时数据和模拟外部接口；真实发消息、删历史、封禁、账号登录或服务变更遵循当前用户授权，不作为普通本地回归的隐含步骤。
